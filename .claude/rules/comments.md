# コメント規約

## 文体

言語は**日本語**。識別子・型名はバッククォートで囲む (例: `OutputFormat`)。技術用語 (EXIF, ICC など) は英語のまま使ってよい。

**文体はです・ます調にしない。** 常体 (だ・である調) または体言止めで書く。

- 良い例: `トリミングして保存する` / `変更がない場合は更新しない` / `失敗時は元の画像を返す`
- 悪い例: `トリミングして保存します` / `更新しません` / `返します`

**1行に複数の文を書く場合を除き、句点 (`。`) は付けない。** 1行1文のコメントは体言止めまたは動詞の終止形で終える。

- 良い例: `余白が無い場合は元の画像をそのまま返す`
- 良い例 (1行に複数文): `四辺の画素を集計する。最多クラスタ内の最頻色を背景色とする。`
- 悪い例: `余白が無い場合は元の画像をそのまま返す。`

**括弧は全角の `（` `）` は使わず、半角の `(` `)` のみを使用する。**

- 良い例: `出力パスが衝突した場合は連番を付ける (既存ファイルは上書きしない)`
- 悪い例: `出力パスが衝突した場合は連番を付ける（既存ファイルは上書きしない）`

**コロンは全角の `：` は使わず、半角の `:` のみを使用する。**

- 良い例: `失敗時: 元の画像を返す`
- 悪い例: `失敗時：元の画像を返す`

## セクション区切り

ファイル内の論理ブロックの前に、次の形式で区切る。長大なファイルをセクション区切りなしで書かない。

```rust
// ======================================================================
// セクション名
// ======================================================================
```

例: `保存`, `ワーカースレッド`, `テスト`, `macOS`

## ドキュメントコメント (`///`)

公開 API・主要な非公開関数・型・enum バリアント・構造体フィールドに付ける。

### 関数

構成は次のとおり。

1. 1行目: 何をするか (要約)
2. 空行
3. 補足説明 (必要な場合のみ)
4. `# Arguments` — 引数が 1 つ以上ある場合 (`self` / `&self` / `&mut self` を含む)
5. `# Returns` — 戻り値の型 (`->`) がある場合

- **`pub fn` は上記の構成を必須とする。** `pub(crate)` や非公開の関数は同構成を推奨するが必須ではない
- 引数がない場合は `# Arguments` を、戻り値が `()` で暗黙の場合は `# Returns` を省略してよい
- 補足説明と `# Arguments` の間、`# Arguments` と `# Returns` の間には空行 (`///` のみの行) を 1 行入れる

```rust
/// 画像の背景色を検出し、余白を除いた範囲を返す
///
/// 四辺の画素を量子化して集計し、最多クラスタ内の最頻 RGBA を背景色とする
///
/// # Arguments
/// * `image` - 検出対象の画像
/// * `tolerance` - 背景色とみなす色差の許容値
///
/// # Returns
/// * `Option<Rect>` - 余白を除いた範囲。画像全体が背景色の場合は `None`
```

### 型・enum・モジュール

- **型・enum:** 役割を説明し、バリアントには1行で挙動を書く。副作用や失敗時の挙動も明記する (例: `失敗した場合は元の画像を維持する`)
- **モジュール (`//!`):** モジュールの責務を2〜3行で説明する (`app/mod.rs` 参照)

## インラインコメント (`//`)

自明な処理には書かない。次の場合のみ使う。

- 非自明なビジネスロジック・エッジケース (例: EXIF Orientation の反映後にサイズを再判定する)
- アルゴリズムの意図・手順
- UI 組み立ての段階
- テスト内の検証ステップ

## テスト

- セクション区切り `// テスト` を使う
- `#[test]` 関数には `///` で検証内容を書く
- **1 行目は `〜すること` で終える** (例: `単色画像は余白なしと判定すること` / `透過 PNG の余白を除去できるようにすること`)
- `〜テスト` / `〜こと` (単独) / `〜ことを確認する` / `〜と確認すること` などの別形式は使わない
- 補足説明が必要な場合は 2 行目以降に書き、**要約行 (1 行目) だけ** `〜すること` を満たせばよい
- テスト本体では、各アサーション群の意図を `//` で簡潔に補足する

```rust
// ======================================================================
// テスト
// ======================================================================

/// 単色画像は余白なしと判定すること
#[test]
fn solid_image_has_no_margin() { /* ... */ }

/// 出力パスが衝突した場合は連番を付けて保存すること
///
/// 既存ファイルは上書きしない
#[test]
fn colliding_output_path_gets_suffix() { /* ... */ }
```

## 書かないこと

文体・句読点・括弧・コロンの禁止事項は「文体」節のとおり。加えて次は書かない。

- コードを読めば分かる処理の説明
- 英語と日本語の混在した冗長なコメント
